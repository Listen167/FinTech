# 获奖创新路线：家庭可信金融代理

## 1. 建议采用的统一背景

项目不再只讲“说话就能办银行业务”，而是聚焦一个更有辨识度的问题：

> 当银龄用户需要家人协助、又最容易遭遇远程控制与冒充诈骗时，如何让 AI 既能代办，又不会失控？

“安心办”定位为面向银龄家庭的可信金融代理。它理解生活语言，但资金权限由确定性策略、本人授权、家庭授权范围和银行回执共同约束。这个背景可以自然串联多轮对话、动态权限、反诈、跨渠道和审计，而不是把它们讲成互不相关的技术点。

## 2. 最值得展示的三个创新

### 2.1 家庭可信授权圈

用户可主动邀请一名家人作为守护联系人，并设置最小化授权范围，例如：

- 只接收高风险事件，不查看完整账单；
- 日常缴费可代确认，转账不能代执行；
- 大额、新收款人或疑似诈骗时需要本人和家人双确认；
- 授权有金额、场景和有效期，并可随时撤销。

这不是简单的“亲情卡”，而是可解释、可撤销、可审计的 Consent Graph。答辩时应强调隐私最小化，避免把守护设计成家庭监控。

### 2.2 反诈冷静期与安全升级

Policy Engine 不只输出通过或阻断，还可以输出 `COOLING_OFF`：

- 命中“安全账户、保密、远程控制、冒充客服”等信号时冻结本次操作；
- 用时间线展示触发证据，而不是只给一个风险分；
- 在冷静期内禁止通过改写 Prompt 重新发起同一收款人交易；
- 经用户授权后，仅向守护联系人发送最少必要的风险提醒；
- 红色验证必须跳转到银行安全页面，IM 中不能直接完成资金授权。

这会让项目从“银行聊天机器人”升级为主动保护用户的安全代理。

### 2.3 操作护照

为每次关键操作生成可验证的“操作护照”，包含：

- 用户原始意图摘要和结构化意图哈希；
- 模型、Prompt、Policy 版本；
- DAG 节点和工具调用结果；
- 风险证据、确认或 MFA 证据；
- 操作快照哈希和银行沙箱回执；
- 完整状态时间线。

评委可以在页面中展开一笔转账，看到“AI 理解了什么、系统为什么允许、用户授权了什么、银行实际执行了什么”。这是目前已有审计能力最容易升级出的视觉亮点，也最能回应银行对可解释和可追责的要求。

## 3. 时间有限时的实现顺序

| 优先级 | 能力 | 原因 |
| --- | --- | --- |
| P0 | 操作护照时间线 | 可复用现有 Run、Policy、MFA 和审计数据，开发成本低，答辩效果强 |
| P0 | 反诈冷静期 | 能形成与普通 Banking Agent 的明显差异，并强化现有反诈规则 |
| P1（已完成） | 家庭守护联系人与双确认 | 已实现一次性邀请、最小 Consent、本人加守护人双确认、即时撤销与审计 |
| P1 | Channel Gateway + 飞书提醒 | 展示 APP 与 IM 连续体验，必须保持高风险操作回到安全页面 |
| P2 | 决策回放与红队评测面板 | 技术答辩加分，但不应挤占主流程完成度 |

不建议优先扩充大量银行业务场景。比赛时间有限时，三个场景做深、形成统一安全故事，比十个浅层工具更容易让评委记住。

## 4. 推荐演示故事

1. 用户用自然语言完成账单体检，Agent 识别异常消费和闲置订阅。
2. 用户取消订阅，黄色权限展示预览并明确确认。
3. 用户向家人转 200 元，可信联系人、小额操作正常确认执行。
4. 用户转 20000 元到新收款人，触发随机 Step-up MFA，并展示操作护照。
5. 用户说“客服让我转安全账户并保密”，系统进入冷静期，阻断同收款人重试，并按授权范围提醒守护联系人。
6. 最后展示一条完整时间线：自然语言输入、风险证据、授权、工具回执和审计哈希。

一句话总结可以使用：

> 安心办不是替用户更快地花钱，而是在 AI、本人、家人与银行之间建立一条可验证的信任链。

# 获奖增强开发清单

## 1. 使用方式

本清单用于基础功能完成后的增强开发。后续按编号逐项实现，每一项必须同时满足代码、测试、文档和演示验收，才标记为完成。

优先级说明：

- `P0`：直接影响项目完整度和答辩可信度，应优先完成。
- `P1`：形成差异化竞争力，在 P0 稳定后实现。
- `P2`：生产化与交付增强，根据比赛剩余时间取舍。

明确边界：比赛版本继续使用银行沙箱；不连接真实资金、不允许 LLM 生成任意工具名直接执行、不在飞书中完成资金确认或提交验证码。

实现记录：`TaskGraphExecutor` 在每次状态转换后持久化检查点，只分派显式注册的后端处理器。确认、MFA 和生活图谱候选均停在 `HUMAN_CONFIRM` 节点；可信授权到达后才恢复受保护写节点。账单、订阅、转账、跨场景分析和生活事件资金规划均已迁移。前端只展示最小回执摘要与引用编号，不展示输入/输出摘要、账户、Token 或验证码。B 阶段安全与恢复场景已纳入全量自动化测试。

验收标准：Run 的最终结果必须能由节点执行记录重建；删除或跳过策略、确认节点时执行器拒绝运行；后端重启后可从可信检查点恢复，但不能重复执行已完成写操作。

答辩展示：同一张图中看到“AI 计划了什么、当前执行到哪里、为何暂停、哪个工具给出最终回执”。

### D. 主动生活事件雷达（P0，已完成）

- [x] D1. 为 `scheduled_actions` 增加待执行、处理中、已发送、失败、取消状态及幂等约束。
- [x] D2. 实现到期扫描 Worker，使用数据库抢占或租约避免多实例重复处理。
- [x] D3. 扫描生日、纪念日、学费日和目标截止日，重新读取最新目标与余额，不信任旧快照。
- [x] D4. 通过飞书发送最小必要提醒；群聊不发送隐私内容，资金操作仍跳回受信 App。
- [x] D5. 增加失败重试、退避、最大次数和人工处理状态，防止无限重试。
- [x] D6. 用户可暂停、恢复或取消提醒，并记录审计。
- [x] D7. 提供演示时间加速能力，但必须明确标记为沙箱模拟时间。

实现记录：雷达 Worker 与 Uvicorn、飞书入站 Worker 分进程运行，使用数据库行锁与可过期租约抢占动作；失败按指数退避，达到上限进入 `MANUAL_REVIEW`。每次发送前重新读取事件、目标和银行沙箱余额，飞书只向绑定用户 `open_id` 私聊发送最小披露文本，并使用稳定 UUID 去重。用户控制和 Worker 状态转换均写入独立审计表。模拟扫描只在显式开启的本地类环境可用，返回 `SANDBOX_SIMULATED_TIME`。详见 `docs/LIFE_EVENT_RADAR.md`。

验收标准：同一到期动作最多产生一次业务提醒；Worker 重启或飞书超时不会重复通知；提醒本身不能执行转账或扣款。

答辩展示：Agent 不再只被动回答，而是在重要日期前主动发现资金风险并提醒用户。

### E. 家庭资金目标协商器（P1，已完成）

- [x] E1. 定义资金目标约束 Schema：目标金额、最低金额、截止日、刚性/弹性、是否可缩减、延期或分期。
- [x] E2. 定义全局资金约束：用户确认的备用金、已承诺支出、允许使用的账户和规划时间范围。
- [x] E3. 使用 DeepSeek 从生活语言提取目标约束和偏好，输出必须通过 Pydantic Schema；缺失或矛盾字段必须追问。
- [x] E4. 为每项约束记录来源与可信度，至少区分 `USER_CONFIRMED`、`BANK_CONFIRMED`、`MODEL_INFERRED` 和 `FORECAST`。
- [x] E5. 模型推断和历史收入预测不得用于保证刚性目标，只有用户或银行确认的收入才能进入保证方案。
- [x] E6. 使用 LangGraph 编排“读取关系圈与目标 -> 补充约束 -> 构建时间线 -> 计算方案 -> 等待选择 -> 生成候选变更 -> 再次确认”。
- [x] E7. 实现确定性现金流时间线，按每个截止日期计算余额、确认收入、承诺支出、备用金和累计缺口。
- [x] E8. 实现确定性方案生成器，优先满足刚性最低金额和备用金，再按截止日期与用户确认偏好分配弹性目标。
- [x] E9. 不依据“配偶、父母、子女”等身份自动决定优先级；人物关系只提供事件上下文，不提供资金支配权。
- [x] E10. 允许 LLM 提议额外方案，但每个方案必须重新经过确定性可行性校验，非法方案直接丢弃并记录稳定错误码。
- [x] E11. 至少生成“缩减金额、等待确定收入、延期、分期、自定义”中的两个可行备选，并明确标记条件方案。
- [x] E12. 每个方案展示逐日期余额、资金缺口、使用的收入证据、受影响目标和计算公式。
- [x] E13. 用户选择后只生成带快照哈希的候选变更；确认前不修改正式生活图谱、不预留资金、不发起转账。
- [x] E14. 用户确认前重新读取余额、目标和收入；快照过期或资金变化时废弃旧方案并重新计算。
- [x] E15. 支持方案对比、拒绝、撤销和人工接管，所有修改保留前后快照、选择理由与审计事件。
- [x] E16. 设计有限自动调整 Consent Scope：金额上下限、备用金、目标范围、单次变动阈值、有效期和随时撤销。
- [x] E17. 比赛版本默认关闭正式目标自动修改；即使在 Consent Scope 内，转账和扣款仍按黄色确认或红色 MFA 执行。
- [x] E18. 前端增加目标时间线与方案对比视图，明确区分“保证方案、条件方案、不可行方案”和“模型解释”。
- [x] E19. 覆盖截止日期先后、收入到账前后、备用金、两个刚性目标同时不足、预测收入落空、模型非法方案和并发余额变化测试。

实现记录：新增资金协商严格 Schema、DeepSeek 约束提取器、确定性现金流规划器和可恢复的 LangGraph 工作流；协商、审计与 Consent Scope 已持久化到 MySQL。候选方案携带快照哈希，确认时在同一事务中重新锁定账户与正式目标，过期方案返回稳定错误并重新计算。前端提供约束编辑、保证/条件/不可行方案对比、逐日余额、选择理由、二次确认、拒绝、人工接管和撤销。比赛版本不自动修改正式目标，也不执行转账或扣款。详见 `docs/FAMILY_FUNDING_NEGOTIATION.md`。

验收标准：面对存款 10000 元、学费 8000 元、礼物目标 3000 元的场景，系统能根据截止日期、确认收入和备用金给出至少两个可解释方案；计算结果可复现，模型不能绕过最低金额、备用金和用户确认。

答辩展示：从“发现冲突”升级为“LLM 理解偏好、算法证明可行、LangGraph 推进协商、用户决定价值选择”的家庭资金方案。

### F. 反诈冷静期（P1，已完成）

- [x] F1. 建立风险事件记录，关联用户、收款人指纹、诈骗信号、触发时间和策略版本。
- [x] F2. 命中安全账户、冒充客服、保密、紧迫或远程控制等高风险组合时进入 `COOLING_OFF`。
- [x] F3. 冷静期内拦截对同一收款人的改写重试，避免通过换一种说法绕过。
- [x] F4. 向用户展示命中的事实证据、冷静期结束时间和安全求助入口。
- [x] F5. 解除冷静期必须通过受信 App 和更强验证；飞书消息不能解除。
- [x] F6. 覆盖误报申诉、过期、跨用户隔离、并发重试和时间边界测试。

实现记录：新增风险事件、释放挑战和审计表，使用用户域 HMAC 收款人指纹与活动唯一键关联跨 Run 重试。高危语义组合进入 `COOLING_OFF`，策略节点和最终转账节点均会检查活动事件。前端展示确定性事实、北京时间、96110 求助、误报申诉和受信 App MFA；飞书只返回安全跳转，不能解除。释放后不恢复原转账。详见 `docs/FRAUD_COOLING_PERIOD.md`。

验收标准：风险指令被阻断后，用户在冷静期内改变措辞仍不能向同一收款人发起交易；普通收款人不受影响。

答辩展示：项目从单句关键词拦截升级为有记忆、有时效、有证据的反诈安全代理。

- [x] G1. 定义可撤销 Consent Scope：通知范围、场景、金额、有效期和可见字段。

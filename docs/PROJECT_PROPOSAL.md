# 安心办 SafeBank Guardian 项目方案

## 1. 项目定位

安心办是面向家庭与银龄用户的安全银行 AI 智能体。它不仅缩短手机银行操作路径，还解决 AI 代办金融业务时最核心的信任问题：系统如何证明 AI 理解了什么、计划做什么、用户确认了什么，以及银行最终执行了什么。

项目口号：**让 AI 能办事，但不能越权。**

## 2. 创作背景

传统手机银行以功能菜单组织业务，而用户通常以生活目标表达需求，例如“这个月钱怎么少得这么快”“停掉没用的会员”“给女儿转两百元”。大模型能够理解这些表达，但一旦进入资金操作，普通对话机器人存在四类风险：

1. 幻觉：工具失败后仍声称操作成功。
2. 越权：提示词要求跳过确认或强验证。
3. 篡改：用户确认 200 元后，执行参数变成 2000 元。
4. 语境缺失：固定金额阈值无法识别“安全账户”“必须保密”等诈骗话术。

安心办因此将“意图理解”和“业务授权”彻底分离。AI 负责理解和规划，独立 Policy Engine 根据金额、操作类型、收款人关系和诈骗语义决定自动执行、用户确认、强验证或阻断。

## 3. 目标用户

- 不熟悉银行功能名称、偏好生活化表达的用户。
- 容易受到冒充客服、紧急转账话术影响的银龄用户。
- 希望快速完成家庭账单、订阅和生活费管理的家庭用户。

比赛版本不实现家庭成员代操作。未来的“可信联系人”仅用于风险提醒，不共享账户控制权。

## 4. 三大核心场景

### 4.1 账单分析：绿色

用户说“帮我看看这个月钱花在哪”。系统读取沙箱流水、完成消费分类、标记凌晨大额消费，并发现长期未使用的周期扣费。该场景只读，自动执行。

### 4.2 订阅取消：黄色

用户说“取消云盘会员”。系统先生成取消预览，展示服务名称、金额和影响；只有用户明确确认后才改变订阅状态。

### 4.3 智能转账：黄色或红色

用户说“给女儿转 200 元生活费”。系统提取联系人和金额，生成不可变预览并要求确认。金额超过 1000 元、新收款人或可疑语义会提升风险；高风险请求要求 OTP，严重诈骗特征直接阻断。

## 5. 创新点

### 5.1 意图级反诈

风险评估不只看金额，还识别“安全账户、冒充客服、立即转账、必须保密、远程控制”等语义，并结合新收款人进行动态升级。

### 5.2 操作护照

每次 Agent Run 保留原始输入、结构化意图、DAG、策略结论、确认或验证状态、工具结果和审计编号。前端以时间线展示，不需要评委查看后台日志。

### 5.3 写操作单独授权

跨场景任务可以自动完成只读分析，但取消订阅和转账不会被合并成一次模糊确认。每个写操作必须绑定独立快照和授权，符合最小授权原则。

### 5.4 双层智能架构

LLM 提供语义理解与风险线索，确定性规则负责最终权限。模型输出只能提高风险，不能降低后端计算出的等级。

## 6. 作品简介（200 字以内）

安心办 SafeBank Guardian 是面向家庭与银龄用户的安全银行 AI 智能体。用户可用生活化语言完成账单分析、订阅取消与智能转账。系统通过结构化意图识别和 DAG 任务规划，将金额、行为异常、新收款人及诈骗语义纳入动态绿黄红分级；高风险操作需强验证，计划、确认和执行结果形成完整审计链，防止幻觉、注入、参数篡改与重放攻击。

## 7. 项目边界

- 当前为比赛沙箱，不连接真实银行和真实短信服务。
- OTP、账户、交易和联系人均为虚构演示数据。
- 当前规则解析器保证离线稳定；配置 OpenAI 兼容接口后可启用真实 LLM 解析。
- 不宣称已达到银行生产系统的监管、隐私和灾备要求。

# 安全自评报告

## 1. 评估范围

本报告覆盖比赛版前端、AI 编排、FastAPI Agent Runtime、Policy Engine 和 Mock Bank Sandbox。所有业务数据均为虚构数据，不连接真实资金系统。

## 2. 权限分级实现

| 等级 | 实现策略 | 当前场景 |
| --- | --- | --- |
| 绿色 | 意图明确后自动执行，只允许读取 | 账单分析、订阅查询 |
| 黄色 | 生成不可变预览，用户明确确认后执行 | 小额转账、取消订阅 |
| 红色 | 操作绑定 OTP 会话，验证通过后执行 | 大额转账、新收款人高风险转账 |
| 阻断 | 不创建可执行授权 | 注入攻击、严重诈骗语义、快照异常、连续验证失败 |
| 冷静期 | 同一用户与收款人持续阻断，仅受信 App MFA 可解除 | 安全账户、远控或多项诈骗语义组合 |

## 3. 威胁与控制

| 风险 | 已实现控制 | 验证方式 | 剩余风险 |
| --- | --- | --- | --- |
| 模型编造成功 | 仅 BankService 返回值可形成成功状态 | 模拟工具失败并检查状态 | 当前尚未接入真实核心银行错误码 |
| Prompt 注入 | LLM 前置规则、中文/英文绕过检测 | 注入评测用例 | 规则无法覆盖所有语义变体 |
| 诈骗诱导 | 安全账户、冒充、紧迫、保密、远控语义信号；收款人 HMAC 指纹；跨 Run 冷静期；执行前复核 | 高危提示词、改写重试、并发旧授权 | 规则仍可能误报或漏报，需要人工调查与生产反诈模型补充 |
| 参数篡改 | 操作快照 SHA-256，执行前复验 | 修改内存动作后确认 | 比赛版内存数据无持久化保护 |
| 重放攻击 | 确认单次使用、预览状态检查 | 重复提交同一确认 | API 网关层仍需限流和 nonce |
| 暴力验证 | 随机 OTP、HMAC 摘要、五分钟过期、三次失败熔断、重发冷却 | 连续输入错误验证码 | 生产仍需短信网关和设备级限流 |
| 越权工具 | 工具白名单、Runtime 固定路由、家庭守护 Consent Scope | 请求未知操作、授权范围越权 | 其他银行开放能力仍需逐工具 OAuth/Consent |
| 敏感数据泄露 | 演示数据虚构、账号脱敏、守护字段白名单和金额区间 | 检查 API 输出 | 生产需字段级加密与日志脱敏 |
| 家庭协助越权 | 定向一次性邀请、双方确认、场景/金额/字段/有效期 Consent、即时撤销 | 第三人兑换、范围越权、撤销后访问和双确认顺序测试 | 生产仍需可信联系人实名核验、设备绑定和授权合规留痕 |
| 守护人代操作 | 守护结果固定为风险已知，永不满足 MFA、永不授权或执行资金 | 跳过本人确认、双方确认后检查安全边界 | 不提供法定代理或共同账户能力 |
| 伪造渠道事件 | Webhook 签名、Verification Token、AES 解密、五分钟时间窗；长连接使用官方 SDK | 错误签名、错误令牌、过期请求和密文篡改测试 | 生产仍需 WAF、来源限速和集中密钥托管 |
| 渠道重复执行 | 消息数据库唯一约束、Agent 幂等键、飞书回复稳定 UUID | 同一事件重复投递并检查 Run 与回复键 | 处理中进程崩溃需要生产消息队列和死信恢复 |
| 渠道身份泄露 | 原始 ID 不进入用户 API；页面只展示 HMAC 脱敏指纹；主动投递标识加密保存 | 检查身份列表响应和数据库字段 | 生产需 KMS 包封加密和密钥轮换 |
| 服务中断 | LLM 失败自动回退，Agent 状态写入 MySQL | 不配置模型密钥启动、重启恢复会话 | 多实例仍需分布式锁和消息队列 |

## 4. 已知限制

1. 当前注入检测以规则为主，不代表可以防御所有对抗样本。
2. 当前短信投递为本地模拟适配器，尚未连接真实短信、设备确认、人脸识别或 U 盾。
3. 比赛版 MySQL 快照同步不支持多实例并发、一致性事务和灾难恢复。
4. 当前已实现登录、资源所有权和家庭守护细粒度 Consent Scope，但尚未接入银行统一身份与真实可信联系人核验。
5. LLM 的结构化结果只做基础字段检查，生产环境需要严格 Schema 和模型输出评估。
6. 审计日志在比赛版中不是不可篡改存储，生产环境应写入独立审计系统。

## 5. 安全结论

当前版本适合作为比赛沙箱，能够展示赛题要求的分级、幻觉防护、注入防御、审计和熔断机制。它不应连接真实银行账户或真实资金。生产化前必须完成身份认证、持久化事务、密钥管理、隐私合规、限流和专业安全测试。
